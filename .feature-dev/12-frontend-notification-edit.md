# Шаг 12 — Frontend: действия уведомления ОВ-11 (submit / edit / delete)

Дата: 2026-07-19 · Стек: React 18 + TS + shadcn/ui + TanStack Query + RHF+Zod · роль admin.

Реализованы три действия над уведомлением из ТЗ §«Правила редактирования и удаления
уведомления (ОВ-11)»: отправить в работу (submit), редактировать (PATCH, гейтинг по
статусу SV-10), удалить (DELETE, гейтинг по приобретениям SV-11). Бэкенд живой на :8000,
типы `schema.d.ts` уже содержали submit/PATCH/DELETE — дописаны только компоненты и
слой данных.

## Гейтинг (UX-слой; сервер проверяет всё равно)

**Отправить в работу** — кнопка видна только при `status === "draft"` → `POST
/notifications/{id}/submit` (draft → in_progress, ручной submit завскладом). Тост об успехе.

**Редактировать** — кнопка видна при `status !== "closed"` (черновик и в работе); для
закрытого недоступна. В `NotificationEditDialog`:
- **Черновик** — полная форма: дата, склад, тексты, строки (add/remove, менять товар и
  количество). Отправляем `date, warehouse_id, body_text, division_name, comment, items`.
- **В работе** — только аддитивно: дата и склад `disabled` (с подсказкой) и не шлются в
  PATCH; тексты правятся; строки — можно добавлять и увеличивать `qty`. Строка, по товару
  которой есть приобретения (`qty_purchased > 0`): селект товара `disabled`, кнопка
  удаления заменена иконкой-замком с подсказкой «Есть приобретения: строку удалить нельзя»,
  у `qty` выставлен `min = приобретено` и подпись «Приобретено: N». Отправляем
  `body_text, division_name, comment, items`.
- **Закрыт** — форма не открывается (кнопки нет), плюс защитная заглушка в диалоге.

Признак «есть приобретения» берётся из реальных данных детали — расчётного поля строки
`qty_purchased` (AP-6, `SUM(acquisition_items.qty)`), которое бэкенд отдаёт в
`NotificationItemRead`. Ничего не выдумано.

**Удалить** — `AlertDialog` с подтверждением. Кнопка `disabled`, когда
`hasAcquisitions` (любая строка с `qty_purchased > 0`; пустой список позиций тоже
трактуется как «нельзя»), с `title`-подсказкой и видимой строкой «Удалить нельзя: у
уведомления есть приобретения». По подтверждению → `DELETE`; при успехе тост + закрытие
детали; при 422 — тост.

## Ошибки сервера — тостером

422-ошибки правки/удаления приходят доменными (`{code, message, details:{}}`, без
`details.errors`), поэтому `applyApiError` отдаёт готовый русский `message` в `toast.error`
без переписывания на клиенте. Проверено вживую (см. ниже): `qty_below_purchased` и
`notification_has_acquisitions`.

## Инвалидация кэша

После submit/patch/delete — `invalidateQueries({ queryKey: ["documents","notifications"] })`.
Это префикс, покрывающий и `...,"list",params`, и `...,"detail",id`, т.е. список и деталь
обновляются одним вызовом.

### Живьём против :8000 (admin/admin12345)

Основной поток (`scratchpad/flow.py`):
1. Создать черновик → `201`, `NOTIF-000001`, `status=draft`.
2. Редактировать черновик полностью (склад 1→2, тексты, строки → оставить только товар 1,
   `qty 10→20`) → `200`, `status=draft`, `wh=2`, `items=[(1,'20')]`.
3. Отправить в работу → `200`, `status=in_progress`.
4. Редактировать «в работе» аддитивно (`qty 20→30`, добавить товар 2, править текст) →
   `200`, `status=in_progress`, `items=[(1,'30'),(2,'8')]`.
5. Удалить «в работе» **без приобретений** → `204`; последующий GET → `404` (удалено).

Пути-отказы (`scratchpad/flow2.py`): черновик → submit → приобретение товара 1 на 4 ед.
против уведомления. Деталь показала `req=10.000, purch=4.000, rem=6.000`.
- Урезать `qty` ниже приобретённого (4 → 2) → **HTTP 422**, `code=qty_below_purchased`
  (доменный message → тост).
- Удалить с приобретениями → **HTTP 422**,
  `message="Нельзя удалить уведомление: есть связанные приобретения"` (тост); кнопка
  «Удалить» в UI для такого уведомления `disabled`.

Все сценарии из задания подтверждены на живом бэкенде.

## (а) Отклонения
- Отчёт лежит в `.feature-dev/` (вне `frontend/`) — так предписано в разделе Deliverables.
- Действия размещены в футере **детали уведомления** (`NotificationDetailDialog`), а не в
  строке списка: только деталь отдаёт позиции с `qty_purchased`, нужные для гейтинга
  удаления и правки «в работе» (`NotificationList` их не содержит). Submit-кнопка для
  черновика также в детали.
- В строке «в работе» с приобретениями кнопка удаления строки заменена на иконку-замок
  (проект не содержит tooltip-компонента) — подсказка через `title`/`aria-label`.

## (б) Вопросы
- Нет. Контракт (submit/PATCH/DELETE, `NotificationUpdate`, `qty_purchased`) полностью
  покрыл требования.

## (в) Что мешало
- В `api`-клиенте не было метода `DELETE` (в системе до сих пор не удаляли ничего, SV-8) —
  добавил `api.del`.
- Тестовые запросы к живому бэкенду ломались об экранирование кавычек и trailing-slash
  редиректы (307) в bash; переключился на Python-скрипты (`urllib`) — прошло чисто.
- В Б--dev осталась одна тестовая запись `NOTIF-000002` (в работе, с приобретением) —
  удалить её нельзя по правилу SV-11; служит демонстрацией гейтинга.
