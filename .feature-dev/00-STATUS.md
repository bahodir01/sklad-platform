## Ключевые инженерные результаты

1. **Найден и исправлен дефект `issue()`** (при ревью архитектуры). INV-2 — немедленный CHECK, не DEFERRABLE; исходный порядок операций ронял бы транзакцию на КАЖДОЙ выдаче. Исправлено на один UPDATE, **доказано под гонкой на живой базе**: двойной клик «Выдано» → ровно одна проводка.
2. **Все инварианты живут в БД, а не только в коде.** 136 CHECK-констрейнтов, составной FK для межтабличного правила INV-4, триггер SV-9, частичные индексы. Проверено попыткой сломать каждый — база отбила.
3. **Контроль перезакупки и минуса кассы держатся под конкуренцией** (`SELECT FOR UPDATE`) — проверено параллельными запросами, не только последовательно.
4. **Гейт контракта** портирован с Django на SQLAlchemy и прогонялся на каждом этапе — код ни разу не разошёлся со словарём данных (22 таблицы, 131 атрибут).
5. **Стек — FastAPI/SQLAlchemy/Pydantic, Django нет нигде** (плагин был Django-ориентирован, переориентирован явно).

## Технический долг (внутренний, не для заказчика)
- **WeasyPrint** (PDF) требует GTK — на dev-машине нет, PDF падает в HTML-фолбэк. В Docker поставится штатно.
- **Celery/Redis** не подняты в dev — фоновые задачи (экспорт, ревизия остатков) реализованы синхронно, но выделены в функции для тривиального выноса.
- **Индексатор codebase-memory** крашится на кириллическом пути «Новая папка» — обойдено латинской копией.
- **Валидатор контракта** на SQLAlchemy — форк оригинального Django-валидатора (`contract_validator_sqlalchemy.py`).
