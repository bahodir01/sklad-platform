# Спецификация: пакетная подпись и учёт передачи в бухгалтерию

**Основание:** согласовано с заказчиком 19.07.2026 (диалог). Меняет модель §6.2/ADR-3.
**Статус:** к реализации. Схема меняется → миграция + правка контракта.

---

## 1. Суть изменения

Подпись перестаёт быть шлюзом «подписал → выдали». Товар выдаётся в течение месяца, а подписи собираются **пакетом** позже. Печать — не по одному документу, а пачкой из одного экрана.

**Расцепление:** физическая выдача товара (списание со склада) и печать+подпись — разные моменты.
- **Списание** — в момент выдачи учителю (в течение месяца), НЕ в конце. Иначе остатки врут весь месяц.
- **Печать+подпись** — позже, пачкой.

**Осознанный компромисс (заказчик принял):** между выдачей и подписью есть окно доверия — товар ушёл, подписи ещё нет.

---

## 2. Статусная модель заявки (`requests.status`)

**Было:** `draft → to_print → printed → issued`.
**Стало:** `draft → to_issue → issued → signed → submitted`.

| Статус | Смысл | Экран-фильтр |
|---|---|---|
| `draft` | сотрудник заполняет | — |
| `to_issue` | подтверждена, ждёт выдачи завскладом | «К выдаче» |
| `issued` | **товар выдан, списан со склада**, ждёт подписи | **«К подписи»** |
| `signed` | подписи собраны, ещё не переданы | **«Подписано»** |
| `submitted` | передано в бухгалтерию | **«Передано»** |

**Списание товара — на переходе `to_issue → issued`** (ledger.post −qty). Это заменяет прежнее списание на `printed→issued`. Гарантии прежние: списание только в одной точке, `FOR UPDATE`, защита от двойного (INV-2 адаптировать под новый переход).

**Миграция старых данных:** `draft→draft`, `to_print→to_issue`, `printed→to_issue`, `issued→issued`. (Прежние «issued» уже списаны — они корректно попадают в «К подписи».)

**INV-2 (проводка):** проводка `writeoff` теперь рождается на `to_issue → issued` (момент выдачи), не на печати. `requests.writeoff_id` заполняется там же. Инвариант «issued/signed/submitted ⟺ writeoff_id IS NOT NULL» (выдана-и-дальше ⟺ есть проводка).

## 3. Пачка печати/подписи

Новая таблица **`signature_batches`** (только для товара):
- `id`, `number` (uniq, авто), `period_from` date, `period_to` date, `created_by` → users, `printed_at`, `signed_at`, `pdf_url`, `created_at`.
- `requests.batch_id` → `signature_batches` (nullable, RESTRICT).

**Печать пачкой:** админ на экране «К подписи» выбирает заявки (галочки) → «Печать» → создаётся пачка, выбранным ставится `batch_id`, `printed_at`, генерируется **один PDF, сгруппированный по сотрудникам** (у каждого свой раздел листа — админ обходит и собирает подписи). Заявки остаются в статусе `issued` (печать статус не меняет — только группирует и даёт признак «напечатано» = batch_id есть).

**Отметка «подписано» — пачкой, с исключениями:** админ жмёт «Пачка подписана» → все заявки пачки `issued → signed`, `batch.signed_at`. Кого не подписали — **снимает галочку**, они остаются `issued` (вернутся в следующую пачку). Работа только с исключениями, не по одному.

## 4. Передача в бухгалтерию (товар И деньги)

Заказчик: интервал «подписано → передано» **варьируется** (иногда сразу, иногда через неделю) — поэтому `signed` и `submitted` — разные состояния, оба видимы.

**Товар:** bulk-действие на `signed` заявках → `signed → submitted`, `requests.submitted_at`, общий `submitted_register_no` (номер передачи, один на пачку передачи). Тоже пачкой + исключения.

**Деньги (`money_expense`):** новое поле `submitted_at` (date, nullable) + `submitted_register_no`. У денег НЕТ этапа подписи (чек заменяет §7.3) — расход готов к передаче сразу после проведения. Bulk-действие «передать» ставит `submitted_at`. Фильтр «Передано / Не передано».

**Реестр передачи** (печатная форма/отчёт): список переданного за дату / по `submitted_register_no` — доказательство передачи, бухгалтерия расписывается в получении. Отдельно для товара и денег.

## 5. Экраны (фронтенд)

### Экран `to-print` (переосмыслен в журнал-трекер)
Заголовок расширить (напр. «Выдачи товара»). Наверху **карточки-фильтры** со счётчиками: **К выдаче · К подписи · Подписано · Передано**. Клик по карточке фильтрует список.
- **К выдаче** (`to_issue`): кнопка «Выдать» (→ `issued`, списание).
- **К подписи** (`issued`): галочки + «Печать пачкой» (→ PDF по сотрудникам) + «Отметить подписано» (пачкой, исключения).
- **Подписано** (`signed`): «Передать в бухгалтерию» (пачкой, исключения) + печать реестра.
- **Передано** (`submitted`): просмотр/история, перепечать копии/реестра.

### Экран касс/расходов денег
Добавить фильтр «Передано / Не передано» + bulk «Передать в бухгалтерию» + печать реестра.
